# macOS — руководство командной строки

Следуйте пронумерованным примерам для конкретной цели. Команды остаются на английском. Панели показывают учебные команды, а не реальную подпись картой. Только результаты возможностей и проверки неподписанного файла получены локально; настоящие PIN, карта и хранилище секретов не использовались.

Для операций с картой нужны поддерживаемое электронное удостоверение, правильный PIN, совместимый USB-считыватель и адаптер. NFC не поддерживается. Для проверки не нужны карта или PIN. Сохраняйте оригиналы. Закрытый ключ остаётся на карте.

## 1. Установите и проверьте доступные возможности

Откройте [Загрузки](/downloads/) и выберите платформу. Архивы CLI содержат терминальные инструменты и MCP; приложение для рабочего стола устанавливается отдельно. Используйте инструкции менеджера пакетов с актуальной версией и отпечатком ключа. Найдите команду и проверьте возможности перед автоматизацией.

## 2. Найдите считыватель и проверьте сертификат

Подключите USB-считыватель и вставьте карту. Выведите считыватели, затем прочитайте сертификат без PIN. При нескольких картах укажите точное имя считывателя и проверьте владельца перед подписью. Это учебные команды; считыватель для руководства не использовался.

<GuideScreenshot src="/img/guide/macos-cli/ru/reader.svg" alt="2. Найдите считыватель и проверьте сертификат" caption="Учебный пример команды.
```sh
esemnbun readers
esemnbun cert --reader "miniLector EVO" --out leaf.der
shasum -a 256 leaf.der
```

## 3. Подпишите PDF или создайте XML-подпись

PAdES-T встраивает подпись и метку времени в PDF. Без пути результата создаётся отдельный `-semnat.pdf`; существующий файл не перезаписывается. XAdES по умолчанию отделённый XML с SHA-256: храните неизменный оригинал вместе с XML. BES без метки времени, T с меткой, C с дополнительными ссылками сертификатов/отзыва. `--enveloping` нужен, когда получатель требует оригинал внутри XML. Форматам с меткой нужна сеть; C получает также сведения статуса.

<GuideScreenshot src="/img/guide/macos-cli/ru/sign.svg" alt="3. Подпишите PDF или создайте XML-подпись" caption="Учебный пример команды. Скопируйте команды ниже, заменив пути и имя считывателя." steps={[{"x": 3, "y": 23.8, "text": "Запустите подпись PDF и введите PIN в скрытом запросе."}, {"x": 3, "y": 53.5, "text": "Создайте уровень XML, нужный получателю."}, {"x": 3, "y": 83.2, "text": "Включайте оригинал в XML только при необходимости."}]} />

```sh
esemnbun sign Contract.pdf Contract-semnat.pdf
esemnbun xades XAdES-T Declaration.txt Declaration.xml
esemnbun xades XAdES-BES Declaration.txt Embedded.xml --enveloping
```

Вводите PIN только в скрытом запросе или через существующий защищённый ввод с `--pin-stdin`. Приоритет: stdin, `MSIGN_PIN`, запрос. Не помещайте PIN в аргументы, снимки, скрипты или журналы. После ошибки PIN остановитесь и проверьте данные; не повторяйте автоматически.

```sh
esemnbun sign Contract.pdf Contract-semnat.pdf --pin-stdin
```

## 4. Проверьте документ и результат

Выберите подписанный PDF/XML. Для отделённого XML укажите папку с неизменными оригиналами. Проверка автономная: целостность, подпись и встроенная цепочка не устанавливают текущий статус отзыва. `ok:true` означает успешное выполнение, а не действительность подписи. Отсутствие распознанных подписей не означает успешную проверку подписанного документа.

<GuideScreenshot src="/img/guide/macos-cli/ru/verify.svg" alt="4. Проверьте документ и результат" caption="Учебный пример команды. Скопируйте команды ниже, заменив пути и имя считывателя." steps={[{"x": 3, "y": 23.8, "text": "Проверьте PDF/XML с папкой оригиналов."}, {"x": 3, "y": 83.2, "text": "Для автоматизации анализируйте status JSON, а не только ok."}]} />

```sh
esemnbun verify Contract-semnat.pdf
esemnbun verify Declaration.xml /home/me/Originals
esemnbun verify --json Contract-semnat.pdf
```

<GuideScreenshot src="/img/guide/macos-cli/ru/unsigned.svg" alt="руководство командной строки" caption="Локальный результат без обращения к карте; вымышленный файл не содержит подписей." steps={[{"x": 3, "y": 16.7, "text": "Для автоматизации анализируйте status JSON, а не только ok."}]} />

```sh
esemnbun verify --json unsigned.pdf
```

`valid` и `unconfirmed` дают код0; второй оставляет доверие неподтверждённым. `invalid`, `incomplete`, `no_recognized_signature` дают код2. Отсутствие оригиналов означает неполноту, а не доказанное изменение. Код1: ввод/использование; 3: неверный PIN; 4: PIN заблокирован; 5: нет карты/считывателя; 6: ошибка сети служб доверия. После ошибки PIN остановитесь. Приложение не разблокирует карту.

## 5. Подключите MCP с явным доступом к файлам

Настройте локальный клиент совместимого протокола с абсолютным путём программы и выбранной доверенной папкой. Укажите существующую физическую папку. Корни, заявленные клиентом, не дают прав. Символические ссылки, обход пути и специальные файлы отклоняются. Без корней доступно только обнаружение. Используется stdio, а не сетевой сервис подписи. Лимит8МиБ; оригиналам XML нужен отдельный явно указанный корень.

<GuideScreenshot src="/img/guide/macos-cli/ru/mcp.svg" alt="5. Подключите MCP с явным доступом к файлам" caption="Учебный пример команды. Скопируйте команды ниже, заменив пути и имя считывателя." steps={[{"x": 3, "y": 58.5, "text": "Выберите установленную программу и ограниченную папку."}, {"text": "Запросите возможности, затем автономную проверку."}]} />

```sh
esemnbun-mcp --root documents=/Users/me/Documents/Signing
```

Начните с `capabilities` и `verify_document`. Вход: `{rootId,relativePath}`; не передавайте PIN или содержимое документа. Возвращаются минимальные метаданные. Клиент может передать их своим внешним сервисам. См. [настройку и правила MCP](https://esemnbun.md/packages/mcp.md). [Настройки и навыки для десяти ИИ-агентов](https://esemnbun.md/docs/integrations/mcp-agents/) (на английском).

```json
{
  "command": "/opt/homebrew/bin/esemnbun-mcp",
  "args": [
    "--root",
    "documents=/Users/me/Documents/Signing"
  ]
}
```

```json
{"input":{"rootId":"documents","relativePath":"Contract-semnat.pdf"}}
```

## 6. Запросите подпись с подтверждением на Mac

Включите брокер подтверждения в Настройках приложения Mac и используйте его приватную папку. Приложение и helper должны работать от одного пользователя. Папка и requests/responses/outputs должны существовать с правами0700. Запустите helper с ней. В клиенте вызовите prepare_signing для PDF, проверьте сертификат/документ в приложении, подтвердите PIN, опрашивайте get_job и получите результат. cancel_job запрашивает отмену, но не отменяет уже созданную подпись. Запросы истекают через5минут, результаты хранятся24часа. Приложение должно работать. Windows и Linux также поддерживают подтверждение через приватную папку своей платформы; проверьте установленную сборку.

<GuideScreenshot src="/img/guide/macos-cli/ru/broker.svg" alt="6. Запросите подпись с подтверждением на Mac" caption="Учебный пример команды. Скопируйте команды ниже, заменив пути и имя считывателя." steps={[{"x": 3, "y": 33.8, "text": "Включите брокер Mac и используйте показанную приватную папку."}, {"x": 3, "y": 76.1, "text": "Подготовьте запрос в клиенте и подтвердите в приложении."}]} />

```sh
esemnbun-mcp --root documents=/Users/me/Documents/Signing \
  --broker-directory /Users/me/PrivateBroker
```

## 7. Явно настройте подпись без присутствия

Этот расширенный режим подписывает без диалога на каждый документ. Отдельно подготовьте секреты, закрепите точный SHA-256 DER сертификата и создайте приватную папку результатов. Используйте ссылки на источники, а не PIN. Сертификат проверяется до чтения секрета и VERIFY. Проверьте карту и источник в своей установке до применения в работе.

<GuideScreenshot src="/img/guide/macos-cli/ru/unattended.svg" alt="7. Явно настройте подпись без присутствия" caption="Учебный пример команды. Скопируйте команды ниже, заменив пути и имя считывателя." steps={[{"x": 3, "y": 27.4, "text": "Укажите ограниченный вход и приватную папку результатов."}, {"x": 3, "y": 80.6, "text": "Закрепите сертификат и выберите ссылку источника секрета."}]} />

```sh
esemnbun-mcp \
  --root documents=/Users/me/Documents/Signing \
  --allow-unattended-signing \
  --signing-certificate-sha256 <CERTIFICATE_SHA256> \
  --signing-output-directory /Users/me/PrivateOutput \
  --pin-source keychain:service:account
```

macOS: `keychain:service:account`, `env:ESEMNBUN_AUTOMATION_PIN` или `onepassword:op://Vault/Item/field`. Linux: `secret-service:service:account`, окружение или1Password. Windows: `credential:eSemnBun-Automation`, окружение или1Password с абсолютным путём op.exe. Отдельно подготовленная запись Keychain/Credential Manager должна разрешать нужный доступ; биометрическое хранилище приложения не ослабляется. Войдите в1Password вне MCP.

Перед запуском замените `<CERTIFICATE_SHA256>` точными64шестнадцатеричными цифрами. Папка должна существовать: macOS/Linux требуют владельца-пользователя и0700; ACL Windows допускает только пользователя, SYSTEM и Administrators.

Перед подписью создаётся `.unattended-signing-lock` в папке результатов. Неверный PIN, прерывание или неопределённая ошибка оставляют маркер и блокируют повтор. Проверьте результат и состояние карты, осознанно устраните неопределённость и только затем удалите маркер и перезапустите. Не автоматизируйте удаление/повтор. Отмена или тайм-аут не доказывают отсутствие подписи.

## 8. Запустите локальное соединение с браузером

Держите bridge в переднем плане во время работы с сайтом на этом компьютере. По умолчанию loopback HTTP18480 и HTTPS18443. Не запускайте GUI bridge или MoldSign на тех же портах. Остановите Ctrl+C. Пакету нужна HTTPS-идентичность localhost. Для нативных диалогов согласия/PIN используйте приложение рабочего стола.

<GuideScreenshot src="/img/guide/macos-cli/ru/service.svg" alt="8. Запустите локальное соединение с браузером" caption="Учебный пример команды. Скопируйте команды ниже, заменив пути и имя считывателя." steps={[{"x": 3, "y": 33.8, "text": "Запустите локальный bridge браузера."}, {"x": 3, "y": 76.1, "text": "Завершите Ctrl+C после работы."}]} />

```sh
esemnbun server
# Ctrl+C
```

Для поддержки укажите версии приложения/ОС, команду без секретов, код и вымышленный пример. Не прикладывайте PIN или конфиденциальные файлы.

## Зашифруйте файл паролем

Карта не нужна. Создайте пароль для файла и передайте получателю по отдельному доверенному каналу. Это не PIN карты. Шифрование создаёт отдельный файл; сохраните оригинал до проверки результата.

Учебный пример команды — операция не выполнялась.

```sh
esemnbun encrypt Contract.pdf Contract.enc
```

## Зашифруйте для владельца сертификата

Попросите у получателя открытый сертификат шифрования (.cer/.der), экспортированный по следующему руководству. Подтвердите отпечаток с владельцем по доверенному каналу. Сертификата только для подписи недостаточно. Для шифрования нужен открытый сертификат, а не карта, закрытый ключ или PIN получателя.

Учебный пример команды — операция не выполнялась.

<GuideScreenshot src="/img/guide/macos-cli/ru/protect-certificate.svg" alt="Зашифруйте для владельца сертификата" steps={[{"x": 20, "y": 25, "text": "Выполните команду со своими файлами.
