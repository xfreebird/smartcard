# iOS Shortcuts implementation — 7 November 2026

The first implementation adds **Open Documents** and **Verify PDF** as iOS app intents and discoverable App Shortcuts. Both require authentication and open the foreground app. The implementation targets iOS 17 and lives only in the iOS application folder, outside the Share Extension.

Verify PDF accepts a selected PDF up to 32 MiB, checks its header, copies it into a unique protected temporary directory, and calls the existing `CoreDocumentVerifier`. File-backed input is read in bounded chunks while security-scoped access is held. In-memory `IntentFile` content is checked before making the app-owned copy; the framework may already have materialized that content. The temporary directory is removed after verification, cancellation or failure. File access errors throw rather than becoming a successful verification result.

The returned enum distinguishes verified offline signatures, invalid signatures, unconfirmed trust and no recognized signature. An empty report is deliberately not labelled unsigned or valid: the current core cannot distinguish every unsupported signature representation from unsigned content. Offline verification does not establish current certificate revocation status.

Full report metadata appears in the existing Verify screen. Its display URL is deliberately not a file URL: the input copy is erased, no external-file permission is retained, and the shortcut does not add a temporary input to document history. Foreground navigation is retained until SwiftUI consumes it, including cold starts. A generation token prevents an older shortcut verification completion from replacing a newer shortcut navigation request.

No shortcut obtains a PIN, chooses a certificate, signs a file, accesses a card, or authorizes a pending signing request. Prepare-for-signing, detached XML companion selection, document entities, Spotlight indexing and Siri schema integration remain subsequent phases. XML stays in the app workflow until a bounded explicit companion-file contract is available.

Titles, parameters, enum display values and errors use extraction-compatible localized resources, with English/Romanian/Russian catalog entries supplied for integration. The default parameter summary uses the localized intent and parameter names. Spoken phrases have a separate iOS `AppShortcuts.xcstrings` resource in all three languages, preserving `${applicationName}`. Device discovery and localized rendering still require runtime validation; localized app actions do not imply voice recognition support in those languages. Apple specifies the separate phrase table and variable syntax in [Migrate custom intents to App Intents](https://developer.apple.com/videos/play/tech-talks/10168/).

Static review checked the installed SDK interfaces: `IntentFile`, `AppEnum`, authentication policy and the parameter overload used here are available before iOS 17. The newer `supportedContentTypes` parameter overload starts at iOS 18, so this baseline uses `supportedTypeIdentifiers`. The foreground flag preserves iOS 17 behavior. Apple documents the file URL/data distinction in [IntentFile data](https://developer.apple.com/documentation/appintents/intentfile/data), and app action discovery in [Getting started with App Intents](https://developer.apple.com/documentation/appintents/getting-started-with-the-app-intents-framework).

No native build, test suite, simulator or Siri/Shortcuts runtime check was run, per the owner's build rule. Required owner validation: clean installation discovery on iOS 17 and newer, locked-device authentication, warm/cold launch routing, revoked file-provider access, duplicate names, malformed and over-limit PDFs, cancellation, repeated concurrent shortcuts, offline verdicts, and full-result navigation. Confirm intent metadata extraction and localized phrases in the signed application before claiming release readiness.
