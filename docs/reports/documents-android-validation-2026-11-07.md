# Android Documents validation — 7 November 2026

The current Android Debug application builds, its targeted tests pass, and native emulator interactions confirm that clearing History preserves Documents across a process restart. Document taps open fresh, read-only signature details. This validation pass also fixed three issues found while exercising the new UI.

## Fixes made during validation

- Debug activity fixtures now explicitly identify successful signed outputs. They previously relied on the old filename-filter behavior, so the new independent library could appear empty in capture scenarios.
- The signature-details modal sizes to its content, with a 90% screen-height maximum and scrollable overflow. Short results no longer create a nearly full-screen empty dialog. The title and Close action stay outside the scrolling body.
- Saved-file access failures use a localized unavailable-document message. The previous generic exception presentation exposed internal app-cache paths and ENOENT/provider error text. The library entry remains available; opening a missing file neither deletes it nor changes History.

Production signing, card selection and PIN handling were not changed.

## Native runtime evidence

Target: dedicated `esb-stamp-review`, serial `emulator-5560`, Android API 36 ARM64. The application was absent when this test session started. Installed the newly built Debug APK; no application-data reset, PIN-vault access or real-card operation was used. Fixtures were fictional activity records and software-key signed documents generated by the current core tests. Transferred signature bytes were compared against their source before assessing their verdicts.

The following checks were exercised, with assertions and UI hierarchy/screenshot evidence:

- **Fresh inspection:** a saved synthetic PDF renders its current signer, signing date, integrity/RSA checks, trust state and certificate disclosure. The software test certificate correctly remains untrusted; this is not production PKI or timestamp evidence.
- **No inspection side effects:** before/after persisted History and Documents were byte-for-byte unchanged by opening and closing details.
- **History clear:** cleared four history events through the actual confirmation dialog. History became empty while both saved-document records remained.
- **Process restart:** force-stopped and relaunched without demo-seeding extras. Documents still contained both records and History stayed empty. Repeated this clear/restart check on the final APK after the localized error fix.
- **Legacy migration:** removed only the library key from a synthetic preference fixture, then launched the application normally. Five existing history events produced two eligible signed-document records; verified-only and browser events were excluded. Previously pruned metadata is not reconstructable.
- **Missing file:** a saved output whose file was unavailable stayed listed; details showed the localized unavailable state. Final UI assertions excluded ENOENT and internal `/data/user/` paths.
- **Detached XML:** missing `contract.xml` showed an unconfirmed state and a choose-original action. Opened the actual Android system file picker, navigated Downloads, and selected the synthetic original. The current signature then showed intact content/RSA and the expected untrusted test-chain warning. The old missing-original message disappeared.
- **Compact landscape:** at a resized 568 × 320 dp viewport, the modal title/Close remained visible and the original-picker action was reachable by scrolling.
- **Small phone and tablet:** reviewed 320 × 568 dp dark and 800 × 1280 dp dark modal layouts. Also reviewed 412 × 915 dp light/dark states and the expanded certificate disclosure. These are resized emulator viewports at 160 dpi, not physical devices or sensor-rotation evidence.

Initial emulator display settings were restored and the task application stopped after capture. Existing shared-storage sample documents were not bulk-deleted or replaced. Native verification used test signatures, never the owner's identity or PIN.
