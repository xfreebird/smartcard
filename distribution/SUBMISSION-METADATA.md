# Localized submission metadata

Generated by `python3 scripts/prepare-store-metadata.py` from `localization/catalog.json:storeMetadata` and `distribution/stores.json`. Validate with `--check`. This directory is an upload preparation package, not evidence of a published or approved listing.

## Locales and fields

| Store | Romanian | English | Russian | Prepared fields |
|---|---|---|---|---|
| Apple iOS/macOS | ro | en-US | ru | Name, subtitle, platform-specific plain-text description, UTF-8 keywords, promotional text, release notes, support/privacy/marketing URLs |
| Google Play | ro | en-US | ru | Title, short description, Android description |
| Microsoft | ro-RO | en-US | ru-RU | Name, short/full Windows description, features, release notes, search terms and URLs in local listing JSON |

Apple currently supports Romanian metadata. Do not label Romanian text as another locale. Apple exports for each platform have their own hardware/output notes. Generic local JSON files retain the `ro/en/ru` filenames and carry the actual store language in `languageCode`.

The generator checks Apple name/subtitle 30 characters, promotional text 170 characters, keywords 100 UTF-8 bytes, Google title 30 / short description 80 / full description 4,000 characters, and Microsoft up to seven search terms at 40 characters each. All descriptions use the stricter 4,000-character limit so they also fit Microsoft's 10,000-character field. Release notes describe this release; Apple does not require a What's New field for a first submission.

The owner requested these domain paths before content exists. They are intentionally marked `usesPlaceholderURLs: true`. The paths must resolve publicly to the correct content before submission; a nonempty URL alone does not satisfy a store's policy. `docs/privacy-policy.txt` has been updated for user-directed portal uploads, embedded browser storage and platform-specific saving; review and publish it before submission.

## Owner-controlled submission fields still required

These are not fabricated or submitted by this preparation task:

- Public privacy/support/terms content and tested reachability.
- Selected distribution countries, price, availability/release choice and licensing decisions.
- Final age-rating/content questionnaires and data-privacy/Data Safety answers based on current app behavior and embedded websites. The browser can display third-party pages and send user-selected files to those sites; avoid blanket claims that all documents stay local.
- Apple review contact phone and current review contact details, export-compliance answers and requested hardware access/review instructions. Existing signing/export does not establish review approval.
- Google developer verification, first app creation (Firefox currently shows “Create your first app”), app access instructions, government-app declarations, target audience, content rating, Data Safety and Play App Signing setup.
- Microsoft package version: current marketing version 0.2.0 produces package 0.2.0.0; the Store requires a nonzero first package component. Choose a compliant release/package version before uploading.
- Microsoft current submission status, pricing/availability, declarations, age rating, privacy and `runFullTrust` justification. Confirm that the package identity exactly matches the reserved product.

Suggested category: Productivity. This is a recommendation for the owner to select in each console, not a submitted value. Do not advertise NFC support, government affiliation, unattended signing or App Store approval.
